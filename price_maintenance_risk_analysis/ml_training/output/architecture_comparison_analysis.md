# 老项目 vs 新工程：为什么老项目全A验证极其优秀(ICIR 0.914)？

## 🔍 **核心差异分析**

### 1. **数据表架构差异**

#### 老项目架构（成功）
```
ml_features_wide (584列) ← 真正的特征宽表
├── placement: 5,208样本，训练数据
└── fake_quote: 563,073样本，全A验证数据

ml_train_wide (样本空间注册表) ← 训练面板存储
└── 存储训练用的面板数据，通过tag还原
```

#### 新工程架构（失败）
```
❌ 没有创建自己的数据表
❌ 直接使用老项目的 ml_features_wide 表
❌ 但处理流程不同，导致特征质量下降
```

### 2. **特征工程差异**

#### 老项目的成功关键

1. **完整的PIT处理**：
   - 行情数据：PIT ≤ 报价日
   - 财务数据：ann_date ≤ 报价日
   - 行业数据：PIT时间点对齐
   - 技术指标：基于PIT数据计算

2. **五步特征选择漏斗**：
   ```
   IV筛选 → PSI筛选 → 相关性筛选 → VIF筛选 → LGB剪枝
   ```
   从400+特征精选18个核心特征

3. **WOE分箱优化**：
   - 使用scorecardpy进行卡方分箱
   - 每个特征最多5箱
   - 自动处理边界值和异常值

4. **严格的训练/验证分离**：
   - 训练：placement样本（定增数据）
   - 验证：fake_quote样本（全A数据，排除定增）
   - 真正的Out-of-Time验证

#### 新工程的失败原因

1. **数据来源混乱**：
   - 没有自己的数据表
   - 直接使用老项目的表但处理不当
   - 特征对齐和匹配有问题

2. **特征选择不当**：
   - 简单相关性选择替代五步漏斗
   - 缺少PSI稳定性筛选
   - 特征数量过多或过少

3. **标签处理问题**：
   - 标签计算不一致
   - 灰度标签边界处理不当
   - 正样本率差异巨大

4. **验证流程问题**：
   - 数据泄露（训练/验证未严格分离）
   - 样本空间不一致
   - 时间切分不当
